# Pocket 使用说明

**Pocket**（口袋百宝箱）：个人小工具箱，代码按 monorepo 拆成两个能力包，CLI 负责组装。

| 包 | 能力 | 典型命令 |
|----|------|----------|
| `@pocket/daily` | 日报整理 + GitHub Pages 站点 | `npm run run:job` / `npm run site` / `npm run notify` |
| `@pocket/bark` | Bark 通讯推送 | `npm run bark -- ...` |
| `@pocket/cli` | 命令入口 | 上面所有命令都走它 |

日报整体流程：

```text
文章来源 → Cursor Cloud Agent 整理 → notes/*.md → site/*.html → Bark（标题 + 短摘要 + Pages 链接）
```

规则：daily 可以调用 bark；bark 不依赖 daily。

---

## 0. 第一次准备

在项目根目录执行：

```bash
cd /path/to/pocket
cp .env.example .env
npm install
```

`.env` 里需要（本地已配过可跳过）：

| 变量 | 说明 |
|------|------|
| `CURSOR_API_KEY` | Cursor Dashboard → API Keys |
| `BARK_DEVICES` | 设备别名列表，如 `daj,lzx` |
| `BARK_KEY_daj` | daj 的 Bark key |
| `BARK_KEY_lzx` | lzx 的 Bark key |
| `BARK_SERVER` | 一般用 `https://api.day.app` |
| `PAGES_BASE_URL` | 如 `https://mangomaster13.github.io/pocket` |

密钥只放在 `.env`，不要提交到 Git。

## 1. 命令总览

所有命令都在项目根目录执行。  
注意：`npm run xxx --` 后面的 `--` 不能省，参数要传给脚本本身。

| 命令 | 作用 |
|------|------|
| `npm run list` | 查看有哪些任务 |
| `npm run run:job -- --job <id>` | 跑完整任务（生成笔记 + 站点 + 推送） |
| `npm run site` | 只把 `notes/` 重建成 `site/` HTML |
| `npm run notify -- --job <id>` | 对已有笔记发 Bark（带 Pages 链接） |
| `npm run bark -- ...` | 单独发 Bark（不跑 AI） |
| `npm run typecheck` | 检查 TypeScript |

查看内置帮助：

```bash
npx tsx packages/cli/src/cli.ts help
```

## 3. 跑分类日报（最常用）

分类（Pages 顶部可筛选）：**world / business / tech / dev / music / horror**

### 3.1 准备文章（可选）

把文章贴进对应 inbox（标题写在 `#` 行，正文写在 `---` 下面）：

```text
inbox/world.md
inbox/business.md
inbox/tech.md
inbox/dev.md
inbox/music.md
inbox/horror.md
```

inbox 为空时走 RSS 兜底；music / horror 若 inbox 和 RSS 都没有内容会跳过（不报错）。

### 3.2 生成全部类别 + 推送

```bash
npm run run:job -- --all
```

只生成不推送：

```bash
npm run run:job -- --all --skip-delivery
```

单跑一类：

```bash
npm run run:job -- --job tech-daily --skip-delivery
```

笔记路径：`notes/<category>/YYYY-MM-DD.md`  
站点路径：`site/<category>/YYYY-MM-DD.html`

### 3.3 指定日期

```bash
npm run run:job -- --job business-daily --date 2026-07-26
```

### 3.4 部署后通知

```bash
npm run notify -- --all
```

会发一条汇总 Bark，链到归档首页。
### 3.6 只推给某台设备

编辑 `config/jobs.yaml` 里对应 job 的 `delivery`：

```yaml
delivery:
  type: bark
  titlePreset: english
  appendDate: true
  targets: [lzx]    # 只推给 lzx；写成 [daj, lzx] 或删掉 targets 表示全部
```

## 4. Bark 单独推送（不跑 AI）

适合测试连通性、整活、临时喊一声。

### 4.1 看有哪些设备别名

```bash
npm run bark -- --list
```

示例：

```text
daj          https://api.day.app
lzx          https://api.day.app
```

### 4.2 看有哪些标题预设

```bash
npm run bark -- --presets
```

当前预设（可改 `config/bark-presets.yaml`）：

| preset | 标题 |
|--------|------|
| `stranger` | 来自陌生人的消息 |
| `english` | 该学英语啦 |
| `finance` | 今日财经速览 |
| `love` | 有人想你了 |
| `boss` | 老板@了你 |
| `system` | 系统通知 |
| `weather` | 今日天气 |
| `reminder` | 别忘了这件事 |
| `secret` | 加密消息 |
| `express` | 你的快递已到达 |
| `focus` | 该专注了 |
| `night` | 晚安小提示 |

### 4.3 用预设标题推送

```bash
# 推给 daj
npm run bark -- --to daj --preset stranger --body "在吗"

# 推给 lzx
npm run bark -- --to lzx --preset english --body "今日笔记已生成"

# 推给全部设备
npm run bark -- --to all --preset love --body "想你了"

# 多个别名（逗号分隔）
npm run bark -- --to daj,lzx --preset system --body "系统测试"
```

### 4.4 自定义标题（不用预设）

中文和空格务必加引号：

```bash
npm run bark -- --to daj --title "来自陌生人的消息" --body "你好呀"
```

标题优先级：

1. `--title`（最高）  
2. `--preset`  
3. 默认 `Pocket`

### 4.5 常用整活示例

```bash
npm run bark -- --to daj --preset stranger --body "在吗"
npm run bark -- --to daj --preset love --body "daj我爱你"
npm run bark -- --to daj --preset boss --body "下午开会，别迟到"
npm run bark -- --to daj --preset express --body "请下楼取件"
npm run bark -- --to lzx --preset focus --body "该背今天的 5 个词了"
npm run bark -- --to all --preset night --body "明天英语笔记见"
```

## 5. 配置文件在哪

| 文件 / 目录 | 用途 |
|------|------|
| `packages/bark` | Bark 推送包（`@pocket/bark`） |
| `packages/daily` | 日报 + 站点包（`@pocket/daily`） |
| `packages/cli` | CLI 入口（`@pocket/cli`） |
| `.env` | 密钥、Bark 设备、`PAGES_BASE_URL`（勿提交） |
| `config/jobs.yaml` | 任务：来源、LLM、推送对象、标题预设 |
| `config/bark-presets.yaml` | Bark 标题预设文案 |
| `inbox/<category>.md` | 手动贴文章（world/business/tech/dev/music/horror） |
| `notes/<category>/` | 生成好的笔记 |
| `site/` | 生成的 HTML（本地预览；Actions 部署到 gh-pages） |

### 5.1 新增一个标题预设

编辑 `config/bark-presets.yaml`：

```yaml
presets:
  coffee:
    title: 该喝咖啡了
    description: 摸鱼提醒
```

然后：

```bash
npm run bark -- --to lzx --preset coffee --body "续一杯"
```

### 5.2 开启金融任务

在 `config/jobs.yaml` 把 `finance-brief` 的 `enabled` 改成 `true`，再：

```bash
npm run run:job -- --job finance-brief
```

## 6. 换 LLM（以后）

当前默认是 Cursor Cloud Agent。若以后要接 DeepSeek / OpenAI，在 `jobs.yaml` 改：

```yaml
llm:
  provider: openai-compatible
  model: deepseek-chat
```

并在 `.env` 填 `LLM_API_KEY`、`LLM_BASE_URL`、`LLM_MODEL`。

## 7. GitHub Actions + Pages（可选）

工作流文件：`.github/workflows/daily.yml`

顺序：生成笔记（不推送）→ 构建 `site/` → 提交 `notes/` → 部署 `gh-pages` → Bark `notify`

一次性设置：

1. 仓库设为 **Public**（免费账号 Pages 要求）  
2. Settings → Pages → Source 选分支 `gh-pages`、路径 `/ (root)`（第一次 workflow 成功后才有该分支）  
3. Secrets：`CURSOR_API_KEY`、`BARK_DEVICES`、`BARK_KEY_daj`、`BARK_KEY_lzx` 等  

公开地址示例：`https://mangomaster13.github.io/pocket/`

本地想先手动跑：

```bash
npm run run:job -- --all --skip-delivery
npm run site
open site/index.html
```

## 8. 常见问题

### 推送失败：device token not found

Bark key 不对。打开 Bark App，复制形如：

```text
https://api.day.app/你的key/任意内容
```

中间那段才是 key，写到 `BARK_KEY_xxx`。

### 标题乱了 / 没生效

参数里有中文或空格时一定要加引号：

```bash
npm run bark -- --to daj --title "来自陌生人的消息" --body "内容"
```

或直接用 `--preset`，少踩坑：

```bash
npm run bark -- --to daj --preset stranger --body "内容"
```

### 笔记生成了但手机没收到

笔记仍会保存在 `notes/`。看终端有没有 `bark ok → xxx` 或 `warning: delivery failed`。  
也可单独测：

```bash
npm run bark -- --to all --preset system --body "ping"
```

### Cursor 报 model invalid

用 `GET /v1/models` 看当前账号可用模型。`jobs.yaml` 里 `model: default` 表示 Auto。
