New to the web platform in May

Source · 2026-07-27 · 数据来源

In May 2026, Chrome 148, Firefox 151, and Safari 26.5 shipped several features that reached Baseline Newly available status. Highlights include the `:open` pseudo-class, stronger container queries, native lazy loading for video and audio, and wider support for Document Picture-in-Picture and the Web Serial API. Chrome 149 and Firefox 152 betas also preview upcoming CSS and API improvements.

英文改写 Readable rewrite

In May 2026, three major browsers reached stable with meaningful platform updates: Chrome 148, Firefox 151, and Safari 26.5. web.dev’s monthly roundup walks through features that matter for everyday frontend work, especially those that have become Baseline Newly available—safe enough, across engines, to consider for production.

Safari 26.5 was largely a fix release, but it also shipped the :open CSS pseudo-class. That selector styles elements in an open state—such as <details> and <dialog>, or form controls like color and date pickers when their picker UI is shown. It offers a cleaner alternative to attribute selectors such as details[open]. With Safari’s support, :open is now Baseline Newly available.

Chrome 148 completed support for name-only container queries. Developers can query a named container without also writing a size or style condition, and without setting container-type on an ancestor when the query is only by name. In the same month, Firefox 151 added style() queries on @container for custom properties, so teams can style children based on values like --theme: dark on a parent. Together, these moves make both name-only and custom-property style container queries Baseline Newly available.

Performance and richer UI also advanced. Chrome 148 added native loading="lazy" for <video> and <audio>, delaying media fetch until content is near the viewport—similar to images and iframes. Firefox 151 brought the Document Picture-in-Picture API to desktop, allowing an always-on-top window with arbitrary HTML, not only a video element. Web Serial expanded too: Firefox 151 supports it on desktop (with a generated site-permission add-on), and Chrome 148 adds Android support for talking to serial hardware such as boards and printers.

Looking ahead, Chrome 149 beta previews CSS gap decorations, more shape-outside functions, Promise-based smooth scrolling APIs, and BFCache eligibility for pages with active WebSockets. Firefox 152 beta adds fuller field-sizing for form controls, plus Notification actions / maxActions and pseudoElement options in getAnimations(). There was no Safari beta this month. For busy developers, the practical takeaway is clear: container queries and open-state styling are becoming default tools, while media lazy-loading and document-level PiP unlock better performance and interaction patterns with less custom code.

中文全文翻译

2026 年 5 月，三大浏览器迎来有实质意义的稳定版更新：Chrome 148、Firefox 151 与 Safari 26.5。web.dev 的月度盘点梳理了对日常前端工作真正有用的特性，尤其是那些已成为 Baseline Newly available、跨引擎足够安全、可考虑用于生产的能力。

Safari 26.5 主要以修复为主，但也正式支持了 CSS 伪类 :open。该选择器可为处于打开状态的元素设置样式——例如 <details>、<dialog>，或颜色、日期选择器等表单控件在弹出界面显示时。它比 details[open] 这类属性选择器更干净、更符合语义。随着 Safari 加入支持，:open 现已成为 Baseline Newly available。

Chrome 148 补齐了“仅按名称”的容器查询支持。开发者可以只按容器名称查询，不必同时写尺寸或样式条件；若只按名称查询，祖先元素也不必再设置 container-type。同月，Firefox 151 为 @container 增加了针对自定义属性的 style() 查询，因而可以根据父级上的 --theme: dark 等值来设置子元素样式。这些进展使“仅按名称”的容器查询与基于自定义属性的样式容器查询都达到了 Baseline Newly available。

性能与更丰富的界面能力也有进展。Chrome 148 为 <video> 和 <audio> 增加了原生的 loading="lazy"，可在媒体接近视口前延迟加载，做法类似图片与 iframe。Firefox 151 在桌面端支持 Document Picture-in-Picture API，可打开包含任意 HTML 的置顶窗口，而不只是视频元素。Web Serial 的平台覆盖也在扩大：Firefox 151 在桌面端支持该 API（需安装自动生成的站点权限扩展），Chrome 148 则在 Android 上增加支持，便于与开发板、打印机等串口硬件通信。

展望未来，Chrome 149 测试版预告了 CSS gap decorations、更多 shape-outside 函数、基于 Promise 的平滑滚动 API，以及存在活跃 WebSocket 时仍可能进入 BFCache 等能力。Firefox 152 测试版则更完整地支持表单 field-sizing，并为 Notification 增加 actions / maxActions，同时在 getAnimations() 中支持 pseudoElement 选项。本月没有 Safari 测试版。对忙碌的开发者而言，实用结论很清楚：容器查询与打开态样式正变成默认工具，而媒体懒加载与文档级画中画能以更少自定义代码带来更好的性能与交互。

单词 Vocabulary

  • Baseline Newly available

    • 英文释义: A compatibility status meaning a feature is supported across the major browsers and is newly ready for broad production use.
    • 中文释义: 表示某特性已在主流浏览器中可用、刚达到可广泛用于生产的兼容状态。
    • 例句: With Safari’s support, the :open pseudo-class becomes Baseline Newly available.
    • 记忆提示: Baseline=基线；Newly available=刚全面可用，可放心上线。

  • pseudo-class

    • 英文释义: A CSS keyword that selects elements in a special state, such as open, hover, or focus.
    • 中文释义: 用于匹配元素特殊状态的 CSS 关键字，如打开、悬停或聚焦。
    • 例句: The :open pseudo-class lets you style elements that have open and closed states when they are open.
    • 记忆提示: pseudo=伪的；class=类——不是真 class，而是“状态类”。

  • container query

    • 英文释义: A CSS rule that applies styles based on a parent container’s size, style, or name rather than the whole viewport.
    • 中文释义: 依据父级容器的尺寸、样式或名称（而非整个视口）来应用样式的 CSS 规则。
    • 例句: With Chrome 148 shipping this month, name-only container queries are now Baseline Newly available.
    • 记忆提示: 问的是“容器”而不是窗口——组件自己决定布局。

  • lazy loading

    • 英文释义: Delaying the download of resources until they are likely to be needed, often when near the viewport.
    • 中文释义: 推迟加载资源，通常等到接近视口、即将需要时再下载。
    • 例句: Chrome 148 introduces native lazy loading for video and audio elements with the loading="lazy" attribute.
    • 记忆提示: lazy=懒——不到跟前不加载，省流量。

  • always-on-top

    • 英文释义: Describing a window that stays visible above other windows even when the user switches focus.
    • 中文释义: 指即使切换焦点也始终显示在其他窗口之上的窗口。
    • 例句: The Document Picture-in-Picture API lets you open an always-on-top window containing arbitrary HTML content.
    • 记忆提示: always on top=永远在最上面，像会议浮窗。

长难句

  • 原句： Previously, when writing a container query, you were required to specify a size or style query condition alongside the container name, and establish the container's type with the container-type property.

    • 结构: 时间状语（when...）+ 主句（you were required to A and B）；A 与 B 为并列不定式。
    • 中文: 过去编写容器查询时，你必须在容器名称之外再指定尺寸或样式查询条件，并用 container-type 属性设定容器类型。
    • 仿写: Previously, when shipping a design system, teams were required to polyfill container queries across browsers, and document every fallback path in the component guide.

  • 原句： Unlike the standard Picture-in-Picture API which lets you view a video element in an always-on-top window, the Document Picture-in-Picture API lets you open an always-on-top window containing arbitrary HTML content.

    • 结构: Unlike + 名词短语（含 which 定语从句）作状语，后接主句对比两种 API。
    • 中文: 与只能把视频元素放到置顶窗口的标准画中画 API 不同，Document Picture-in-Picture API 可打开包含任意 HTML 内容的置顶窗口。
    • 仿写: Unlike a toast library which only shows plain text alerts, a portal-based overlay lets you render interactive forms that stay above the main app shell.

  • 原句： Just like image and iframe elements, you can now instruct the browser to delay loading media resources until they are close to the viewport.

    • 结构: Just like... 比较状语 + 主句；until 引导时间状语从句。
    • 中文: 就像图片和 iframe 元素一样，你现在可以指示浏览器推迟加载媒体资源，直到它们接近视口。
    • 仿写: Just like deferred analytics scripts, you can now instruct the app to delay loading heavy charts until users scroll near the dashboard section.
